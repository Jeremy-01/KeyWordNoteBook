## 二、总体说明
各类网站和产品的账号和密码又多，每个网站对于密码的要求又不同，
时间长了会记不住这些密码和账号。
好记性不如烂笔头，安全的将自己的账号和密码记录到文件中是有必要的
这就要求能够对密码进行加密，防止泄露。

本项目使用JSON格式保存网站、账号和密码等信息，并基于密码学方法，
对密码字段进行加密，防止文件泄露造成损失

基本功能：
使用JSON保存网站、用户名、密码、密码等级提示，关联账户，备注说明等字段，
按照长度、是否区分或强制大小写字母，是否支持或强制特殊符号生成密码等级提示
对常用密码进行分级、加密保存， 并提供了便于操作的用户界面

JSON文件中的标准化词条如下

     load_dict = {
        "ARGON2_PARAMS":Argon2Params            # 加密参数
        "ItemList":ItemDict                     # 存储条目
        "FrequentlyKeys":FrequentlyKeyDict      # 常用条目
        }
    其中：
    ARGON2_PARAMS = {                           
        "kdf_version": int,                    # KDF版本（用于兼容迁移）
        "verify_hash": argon2id_str,            # 验证哈希数
        "hash_len": int,                        # 哈希结果长度
        "encryption_salt": base64_str,          # AES加密盐
        "hmac_salt": base64_str,                # HMAC盐
        "hmac_key_encrypted":str,               # 加密存储HMAC密钥
        "integrity_check": str                  # HMAC完整性校验值
        }
    ItemDict = {
        "1":KeyItem,                            # 第一条用户数据
        "2":KeyItem,                            # ...
        ...
        }
    FrequentlyKeysDict = {
        "1":FrequentlyKey,                      # 第一条常用数据
        "2":FrequentlyKey,                      # ...
        ...
        }
    条目：
    KeyItem = {
        "Index": str,                           # 条目序号，唯一ID
        "PasswordLevel": int                    # 密码等级
        "URL": str,                             # 使用的网址
        "UserName": str,                        # 用户名
        "Password": str,                        # 密码，在文件中使用密文储存
        "LinkURL": str,                         # 关联账户
        "Note": str                             # 备注
        }   
    常用条目：

        }

## 三、安全设计
### Core:
密码等敏感信息采用AES算法进行加密保存，AES密钥本身长度较大，而且常采用随机数，不便记忆。
因此采用二级派生的算法，利用用户自主设定的主密钥派生获得安全的AES密钥
为了防止密码本文件本身被篡改或损坏，利用HMAC算法对文件进行签名和完整性校验。
因此主要的密钥派生关系和用法如下：

    主密钥--argon2->验证哈希
    主密钥+AES盐--argon2->AES密钥
    主密钥+HMAC盐--argon2->HMAC密钥
    HMAC密钥--AES->加密存储，降低HMAC派生开销
    文件--HMAC->校验值，对比文件是否被篡改
    词条--AES->加密存储词条
API的安全性设计：

    API主要提供了登录密码验证、增加、删除、修改、查看非密信息、查看加密数据
    除获取非密信息外的API函数，均需要进行二次密码验证
### UI:
    UI仅负责与用户交互和提供图形化显示，本身不保存任何信息，全部由Core的API函数进行处理
    UI在获取用户输入的明文密码后，仅在API函数调用中传递，在内存中短暂暴露。
    UI获取Core返回的解密数据后，任何操作都会重新覆盖显示信息
    剪贴板敏感信息支持两种到期处理模式：默认仅在内容未改写时自动清空，或可配置为到期后强制清空。
    状态栏会区分显示“已自动清空 / 已强制清空 / 未清空（用户已改写）”。

## 六、使用与协作说明
### 1. 本地数据文件
`my_key.json` 用于保存本地密码本数据，包含敏感信息，不应提交到版本库。

如果历史版本中 `my_key.json` 已被跟踪，建议在仓库中删除该文件并继续仅保留本地副本，仓库仅使用 `my_key.example.json` 作为结构模板。

仓库仅保留 `my_key.example.json` 作为结构示例。程序首次运行且找不到 `my_key.json` 时，会自动初始化新的密码本文件。

### 2. 首次启动流程
#### 情况 A：本地不存在 `my_key.json`
1. 启动程序后，输入你要使用的主密码。
2. 程序检测到本地不存在真实密码本文件，会自动初始化新的 `my_key.json`。
3. 初始化时会自动生成：
   - 主密码验证哈希 `verify_hash`
   - AES 加密盐 `encryption_salt`
   - HMAC 盐 `hmac_salt`
   - 加密存储的 HMAC 密钥 `hmac_key_encrypted`
   - 文件完整性校验值 `integrity_check`
4. 初始化完成后进入主界面，后续新增条目会写入这个本地文件。

#### 情况 B：本地已经存在 `my_key.json`
1. 启动程序后输入主密码。
2. 程序会先加载 `my_key.json`，检查字段完整性。
3. 然后验证主密码是否匹配 `verify_hash`。
4. 验证通过后继续校验文件完整性，全部通过才进入主界面。

### 3. 示例文件与真实文件的区别
- `my_key.example.json`：仓库内的结构示例，用来说明 JSON 组织形式，不包含真实密码数据，也不能直接作为已初始化密码本使用。
- `my_key.json`：程序实际读写的本地密码本文件，包含运行时生成的参数和你自己的加密条目，应仅保留在本机。

如果你是首次接触这个项目，可以把 `my_key.example.json` 当成“格式参考”，把 `my_key.json` 当成“程序运行后的真实数据文件”。

### 补充：浏览器密码导入（Edge / Chrome 等）
主界面顶部提供“导入”按钮，可导入浏览器导出的密码 CSV 文件（如 Edge、Chrome 的导出文件）。

建议流程：
1. 在浏览器密码管理页面先执行“导出密码”，得到 `.csv` 文件。
2. 在本程序中点击“导入”，选择该 CSV 文件。
3. 通过二次密码验证后，程序会批量写入有效条目，并提示成功/跳过/失败数量。

说明：导入时至少需要 `网址(URL)` 和 `密码(Password)` 字段；缺失这两个字段的行会被跳过。

### 4. 当前版本限制
- 当前仅支持默认密码本文件路径，不支持多用户切换。
- 主窗口中的 URL 当前仅作文本展示，不会直接调用默认浏览器打开。
- 登录窗口与主窗口仍使用当前界面样式，未扩展更多自定义标题栏行为。

### 5. 环境变量（剪贴板安全）
- `KEYWORD_NOTEBOOK_CLIPBOARD_CLEAR_MS`：剪贴板到期清理毫秒数，默认 `20000`。
- `KEYWORD_NOTEBOOK_CLIPBOARD_FORCE_CLEAR`：是否启用强制清空模式，支持 `1/true/yes/on`（默认关闭）。
